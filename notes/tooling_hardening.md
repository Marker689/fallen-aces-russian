# Tooling Hardening — Summary

Дата: 2026-08-14. Выполнена защита конвейера `tools/` по пунктам
`notes/improvement_report.md` (раздел 2.1–2.5, частично 2.6/2.7).

## Что изменено

### 1. Пути конфигурируемы — `tools/_paths.py` (НОВЫЙ)
- Все пути читаются из переменных окружения с безопасными значениями по умолчанию,
  равными прежним хардкод-путям (поведение без окружения НЕ меняется):
  - `FALLEN_ACES_GAME`  (по умолчанию `/mnt/c/.../Fallen Aces`);
  - `FALLEN_ACES_BACKUP`(по умолчанию `/mnt/c/.../Fallen Aces_backup_txt`);
  - `FALLEN_ACES_OUT`   (по умолчанию `~/fallenaces-rus`).
- Экспортирует `GAME`, `BACKUP`, `OUT`, `MOD` и хелперы:
  - `resolve_source(rel)` — поиск исходника: сначала бэкап, затем игра; иначе `None`;
  - `source_root()` — корень источника для экстракторов (бэкап приоритетно);
  - `mod_path(rel)` — преобразование пути AcesData → путь внутри `mod/`.

### 2. `tools/_common.py` (НОВЫЙ)
Единственные реализации общих функций (устранено дублирование из extract/verify/
make_packs/inject):
- `make_id(file, line_no)` — id субтитров (md5 `"file:line_no"`, 12 hex);
- `make_id_orig(file, orig)` — id остатка поверхностей (md5 `"file|orig"`, 16 hex);
- `load_translations(glob_pattern)` — загрузка `*.out.json` (пустые переводы
  отбрасываются).

Алгоритмы генерации id НЕ изменены — проверено, что все 2136 id в `packs/*.out.json`
и 447 id в `rest_strings.json` совпадают с вычисленными по этим функциям.

### 3. `extract.py`, `extract_subtitles.py`, `extract_rest.py`
- Пути берутся из `_paths`; экстракторы теперь читают из **бэкапа** (источник
  истины по AGENTS.md), а не из живой игры, которая может быть изменена пилотом.
  Раньше при установленном переводе экстракторы вытаскивали уже переведённый
  русский текст. После правки `extract_subtitles.py` воспроизводит эталонный
  `subtitle_strings.json` побайтово, `extract_rest.py` — тот же набор из 447 id.
- Если ни игры, ни бэкапа нет — печатается понятное сообщение, без traceback.
- `extract_rest.py` использует общий `make_id_orig` (поведение идентично).

### 4. `make_packs.py`, `make_packs_rest.py`
- Используют общий `make_id` / пути из `_paths`. Выходные `.in.json` батчи
  побайтово идентичны зафиксированным (проверено diff-ом по всем батчам).

### 5. `inject.py`
- Использует общие `make_id`, `load_translations`, пути и `resolve_source`.
- Замена по-прежнему индексируется по `line_no` (уже корректна для дублей).
- Выход `mod/Subtitles` побайтово идентичен зафиксированному (511 файлов).

### 6. `inject_rest.py` — ИСПРАВЛЕН баг replace count=1
- Было: `new_txt.replace(orig, new, 1)` — переводился только ПЕРВЫЙ экземпляр
  дублированной строки, остальные молча оставались английскими.
- Стало: замена выполняется ОДНИМ проходом регулярным выражением по всем
  вхождениям каждого `orig` (id контент-основан — одинаковый orig в файле
  переводится целиком). Вставленные переводы не пере-матчатся последующими orig.
- Добавлен предупредительный вывод о непереведённых остатках (LEFTOVER).
- Проверено синтетическим тестом: старый код оставлял дубль английским, новый
  переводит оба вхождения.
- Для всех файлов, кроме известных «дрейфовых» (см. ограничения), выход побайтово
  совпадает с зафиксированным модом.

### 7. `verify.py` — переписан
- Реализована проверка числа строк (была no-op): число строк в файле сверяется
  с оригиналом. Плюс UTF-8 без BOM и валидность UTF-8.
- Основной режим `--target mod` (по умолчанию) проверяет **собранные файлы в
  `mod/`**, а не живую игру.
- Режим `--target game` сохранён для обратной совместимости (проверка живых
  файлов AcesData).
- Работает без игры: если ни игры, ни бэкапа нет — проверяет BOM/UTF-8/полноту,
  для числа строк и структуры выводит явное сообщение о пропуске (без traceback).
- Проверка структуры вне кавычек — как предупреждение (не ошибка), т.к. перевод
  легально может объединять несколько кавыченных фрагментов в строке.
- Сохранена проверка полноты перевода (id в `packs/*.out.json`).

## Проверка (регрессия)
- `python3 -m py_compile` — все изменённые скрипты компилируются без ошибок.
- `extract_subtitles.py` → `subtitle_strings.json` побайтово идентичен эталону.
- `make_packs.py` → батчи `.in.json` побайтово идентичны зафиксированным.
- `inject.py` → `mod/Subtitles` побайтово идентичен зафиксированному.
- `inject_rest.py` → идентичен зафиксированному для всех файлов, кроме дрейфа.
- `verify.py --target mod` → на эталонном моде: 0 ошибок по субтитрам, 2 ошибки
  числа строк и 9 структурных предупреждений (все — из-за дрейфа бэкапа, см. ниже).
- `verify.py --target game` → 0 проблем.
- `verify.py --target mod` без игры/бэкапа → корректный деградационный режим,
  exit 0.

## Остаточные ограничения (НЕ исправлено, вне рамок задачи)
- **Дрейф данных**: зафиксированный `mod/` и рабочие `rest_strings.json`
  устарели относительно текущего бэкапа игры (игра обновлялась):
  - `mod/Episodes/.../Halprinnote.txt`, `mod/loadingScreenTips.txt` расходятся по
    числу строк с бэкапом (потому verify честно сообщает об ошибках числа строк);
  - `mod/Episodes/.../musicSheet.txt`, `Halprinnote.txt` содержат перевод с
    литеральными `\n`, отличающийся от текущего `.out.json`;
  - рабочий `rest_strings.json` создан старой версией экстрактора (у советов
    загрузки пустые prefix/suffix вместо `"`). Актуальный `extract_rest.py`
    генерирует корректные кавычки — для пересборки мода нужно перегенерировать
    `rest_strings.json`.
- **Экстракторы читают бэкап**: поведение изменилось осознанно (см. п.3), чтобы
  конвейер не зависел от изменённой игры. Это соответствует AGENTS.md, но меняет
  источник данных экстракторов.
- **Проверка числа строк зависит от оригинала**: без игры/бэкапа (или без
  зафиксированного справочника) число строк не проверить — verify пропускает её с
  явным сообщением. Для полноценной CI-проверки числа строк нужен зафиксированный
  справочник исходных строк или доступ к бэкапу.
- **Проверка `SpeakDialogue`-ссылок** (что упомянутый файл субтитров существует)
  не реализована — резолв имени персонажа нетривиален; оставлено на будущее.

## Замечание о новых файлах и .gitignore
`tools/_paths.py` и `tools/_common.py` — новые исходники конвейера. В `.gitignore`
есть глобальное правило `*.json`, но эти файлы — `.py`, поэтому не затрагиваются.
Если позже понадобится зафиксировать справочник числа строк как `.json` под
`tools/`, потребуется точечное исключение в `.gitignore`.
